# isp_replace

`isp_replace` replaces the non-operational pixels of an image: a defect map with one bit per pixel marks them, and
every marked pixel is replaced by an interpolation between the nearest operational pixels of the same line. The
defect map is an ECC-protected, scrubbed table that the software writes through an AXI4-Lite slave; after power-up
the software clears it with `CTRL.CLEAR` or writes it completely. The module is built from
[`isp_frame_sync`](../isp_frame_sync/README.md), an [`isp_window`](../isp_window/README.md) of one line and an
interpolation kernel.

## Tests

Prerequisites: those of the repository (GHDL, the Python packages of `requirements.txt`, the submodules).

```shell
python run.py -p 4 "*isp_replace*"                               # all tests in all configurations
python run.py -v "*isp_replace_tb.g2.test_map_update"            # one test with its log
```

| File | Content |
| --- | --- |
| `src/isp_replace.vhd` | The module |
| `src/isp_replace_regs_pkg.vhd` | Register addresses and fields, generated by `tools/regmap.py` from `regs/isp_replace_regs.yml` |
| `regs/isp_replace_regs.yml` | Register description |
| `tb/isp_replace_tb.vhd` | Testbench: the module, the shared source and sink, the register script on the AXI4-Lite BFM of UVVM, the injection script for the error injection and the scrubber enable, the counts of the status and scrubber pulses, the monitor of the control and status outputs, the timing checks of test_rate and the flag sweeps of test_flag_coincidence |
| `tb/vunit_config.py` | Configurations, the image stream, the register script (defect maps) and the injection script of every test; runs the reference model `replace` of `tools/isp_model.py` |
| `../../lint/isp_replace_synth.vhd` | Wrapper for `lint/synth_check.py`: sets the real generics from integer generics, which GHDL can set on the command line |

The shared components (`tb/isp_tb_source.vhd`, `tb/isp_tb_sink.vhd`, `tb/isp_tb_axilite_pkg.vhd`,
`tb/isp_tb_inject.vhd`, `tools/isp_model.py`, `tools/isp_tbgen.py`) are described in the
[testbench components](../../docs/testbench.md).
